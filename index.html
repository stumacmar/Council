Why Council

One perspective is how good decisions go bad

A single answer — from a person or a model — carries a single bias. Council forces structured disagreement before you commit.

Blind spots, surfaced

Risks, missing stakeholders, and bad timing rarely appear in a single optimistic answer. Seven adversarial lenses make them unavoidable.

Disagreement by design

The agents aren't built to agree. Each one votes independently with a confidence level — and the tension between them is where the insight lives.

A paper trail, not a vibe

Every run writes the full reasoning, vote table, and verdict to shared_reasoning.md — an audit trail you can revisit, share, or defend.

How it works

From question to verdict in four moves

One command in Claude Code. The orchestration, debate, and synthesis happen for you.

Ask the council

Type /council followed by any decision — strategy, money, hiring, timing — in plain language.

Seven agents deliberate

Each specialist analyses the question through its own lens, in parallel — so a full council costs barely more time than one answer.

Every voice on record

Agents append their full analysis, vote, and confidence to a shared shared_reasoning.md file.

The verdict is synthesised

You get a vote table, the points of agreement and conflict, open questions — and a final PROCEED / DO NOT PROCEED call.

The seven

A bench of specialists, not a chorus

Each agent owns one hard question and is rewarded for pressing it — not for being agreeable.

Optimist

What could go right?

Maps the upside: best-case outcomes, favourable conditions, and the second-order wins everyone else discounts.

Devil's Advocate

What could go wrong?

Stress-tests every assumption, names the most likely failure mode, and says the uncomfortable thing out loud.

Realist

Is this actually feasible?

Prices the plan in time, money, and people — then proposes the minimum viable version if the full one doesn't hold.

Strategist

Is this the right move now?

Weighs timing, opportunity cost, and reversibility — including the option everyone forgets: doing nothing.

Stakeholder Advocate

Who is affected, and how?

Maps who wins, who pays, and who isn't in the room — surfacing trust, fairness, and relationship costs early.

First Principles

Are we asking the right question?

Strips the decision to fundamentals, challenges the framing, and checks whether a simpler path reaches the same goal.

Historian

Has this been tried before?

Brings precedents, analogies, and pattern-matches from past decisions — including the ways this exact move has failed before.

The output

A verdict you can defend

Not a wall of text — a vote table, the live disagreements, and a recommendation with its conditions attached.

Council decision analysis

Should we restructure the finance function before the audit?

Agent Vote Confidence Key point
Optimist PROCEED Medium Clean structure signals maturity to auditors
Devil's Advocate DO NOT PROCEED High Restructuring mid-audit creates process gaps
Realist WITH CONDITIONS High 6–8 weeks minimum; not enough runway before Q3
Strategist WITH CONDITIONS Medium Right direction, wrong timing — defer to post-audit
Stakeholder Advocate DO NOT PROCEED High Team uncertainty will harm audit cooperation
First Principles WITH CONDITIONS Medium Real question is when to announce, not whether
Historian DO NOT PROCEED High Pre-audit restructures consistently widen audit scope

Final recommendation

PROCEED WITH CONDITIONS

Defer implementation until the audit completes. Lock the decision and communicate intent internally now to retain key staff, but hold execution until Q4. Three of seven agents voted against on timing grounds; the council agrees the restructure is directionally correct.

Two modes

Full deliberation, or a fast read

Match the weight of the process to the weight of the decision.

/council

Full council

All seven agents, complete synthesis. For decisions you'll have to defend later.

  • Board-level calls — restructures, investments, big commitments
  • Stakeholder mapping, precedent checks, and framing challenges included
  • Full consensus map: where the council agrees, disagrees, and what's unresolved
/council-quick

Quick council

Optimist, Devil's Advocate, and Realist only. For everyday choices that still deserve scrutiny.

  • Lower-stakes decisions — purchases, renewals, scheduling
  • Upside, risk, and feasibility in one pass
  • Same vote table and verdict format, smaller bench

Get started

Installed in under a minute

No build step, no dependencies — Council is just markdown files that Claude Code discovers automatically.

Terminal 
# Clone Council
git clone https://github.com/stumacmar/council.git

# Copy .claude/ into your project
cp -r council/.claude /path/to/your-project/

Claude Code picks up the agents and the /council commands automatically when you run it from the project directory.

Terminal 
# Clone Council
git clone https://github.com/stumacmar/council.git

# Install globally — available in every project
mkdir -p ~/.claude/agents ~/.claude/commands
cp council/.claude/agents/* ~/.claude/agents/
cp council/.claude/commands/* ~/.claude/commands/

A global install makes /council available in every Claude Code session on your machine.

Field notes

Getting the most from the council

Build a decision log Save each shared_reasoning.md to a /decisions/ folder. It becomes an audit trail that's invaluable for board reviews and post-mortems.
Parallel means cheap A full seven-agent council takes roughly the same wall-clock time as a single response — don't reserve /council-quick for speed alone.
Know your power pairings Strategist + First Principles is the strongest duo for board-level calls. Stakeholder Advocate is essential for anything touching organisational change.
Council on the go On mobile, create a Claude Project with the council prompt in its instructions — same structured output, no Claude Code required.
Summon one specialist Need just a precedent check? Invoke any single agent directly via Claude Code's Task tool — the Historian alone is often enough.
Sharpen the question Include constraints — budget, deadline, who's involved. The more concrete the question, the sharper the disagreement, and the better the verdict.
